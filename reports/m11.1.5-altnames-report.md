2. **4 scripts:**

   - `merge_altnames_v2.py` — finds new historical_alias_v2 matches
   - SQL file applied via parallel HTTP API (11.5s for 289 updates)

3. **Loaded 767,572 alt names** into D1 in 46.4 minutes
   - 4,314 historic names (is_historic=1)
   - 18.2M total alt names skipped (not in our cities_staging)

## What we learned

1. **D1 HTTP API is 4x faster than wrangler per-statement** for large loads:
   - wrangler per-batch: ~5s/call (process spawn overhead)
   - HTTP API direct: 0.2s/req with 16 workers
   - For 767K rows, wrangler would have taken ~10 hours; HTTP API took 46 min
   - **Use HTTP API directly for any load > 10K rows**

2. **D1 has a 100-var/statement limit on HTTP API too** (not just wrangler):
   - 9 cols × 11 rows = 99 vars (works)
   - 9 cols × 50 rows = 450 vars (fails with "too many SQL variables")
   - Use BATCH=11 for 9-col tables, BATCH=16 for 6-col, BATCH=8 for 12-col

3. **The historical_alias_v2 hits are small but high-quality**:
   - 12 actual renames caught (Ragusa→Dubrovnik, Vila Rica→Ouro Preto)
   - The other 277 candidates were already covered by M11.1
   - This confirms M11.1's historical_alias tier was already doing good work
   - The marginal value of alt_names is mostly for search, not for merging

4. **M11.1's `WHERE merge_method NOT IN ('exact', 'geonames_only')` was right**:
   - Don't overwrite a precise match with a fuzzy/alias match
   - The 277 skipped candidates were correctly skipped

## Known limitations

1. **Only 12 of 289 candidates updated**: 277 were already better-matched
   by M11.1. This is correct behavior, but it means the alt_names data
   mostly helps *future* features (search, autocomplete) rather than
   *immediate* layer changes.

2. **No population data in alternateNamesV2** — that's in the main
   cities5000.txt which we already ingested.

3. **No elevation in alternateNamesV2** — same.

4. **4,314 historic names is a small sample** — most historic renames
   have been recorded in the GeoNames data, but some aren't (e.g. the
   Soviet-era "Stalinogorod" example I found has only 1 GeoNames
   record of that name).
