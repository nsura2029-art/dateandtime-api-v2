# M11.7: Census of India 2011 — Result Report

**Date**: 2026-08-03
**Branch**: feature/m11.7-census-india
**Status**: API deployed, 422 cities loaded

## What was added

Adds a `censusIndia` block to `/api/v1/cities/{id}` for Indian cities that
were matched to the 2011 Census PCA-UA dataset. The block includes the
official 2011 Indian Census data: population, sex ratio, literacy rate,
workers, and the parent Urban Agglomeration (UA) info.

## Data source

**Census of India 2011, Primary Census Abstract - Urban Agglomeration (PCA-UA)**
- **URL**: https://censusindia.gov.in/nada/index.php/catalog/45261/download/48987/PCA11-UA-0000.xlsx
- **Format**: XLSX, 1.98 MB
- **Records**: 3,319 (298 Level 0 UAs + 1,946 Level 1 statutory cities + 902 Level 2 OGs + 3 Level 3)
- **Released**: 2011 (still the latest official Indian census as of 2026; 2021 delayed by COVID)

## Coverage

- **422 Indian cities matched** to our 7,467 Indian cities (5.7%)
- **23 states** represented
- **236 distinct UAs** (parent Urban Agglomerations)
- **130.9M total population** matched (out of India's 1.21B in 2011)
- **3,762 unmatched**: mostly tier 3/4 towns that don't have state assignment in our DB

**Why so few matched?** The 3,762 unmatched are mostly smaller towns (census_towns, villages). The 1,946 Level 1 + 298 Level 0 = 2,244 census records cover only statutory cities and UAs. Many tier 3/4 Indian cities in our DB don't have a state_id assigned, so the (state, name) join fails. Future improvement: add a (country, name) fallback for cities without state.

## Gotchas hit

- **Variable shadowing bug**: M11.6 used `const c` for Eurostat row, M11.7 used `const c` for census row — but `c` is the Hono context. Caused `ReferenceError: Cannot access 'c2' before initialization` on Indian cities. Fixed by renaming M11.7's row variable to `censusRow`.
- **State table name**: Used `states` but actual table is `administrative_regions` with `type='state'` filter. Fixed.
- **NaN in derived metrics**: `Math.round((female * 1000) / male)` returns NaN if any input is null. Zod's `z.number().nullable()` rejects NaN. Fixed by checking `male_population > 0` and `population > 0` before dividing.
- **GH push protection**: Same as M11.6 — use `${CLOUDFLARE_API_TOKEN:?...}` bash syntax instead of inline `cfat_xxx` literals.
- **D1 ~100-var limit**: 26-col INSERT, BATCH_SIZE=4 needed (104 vars). Loader uses 1-row at a time so no issue.
- **D1 store_error during LAU loader**: LAU loader was hammering D1 with writes. The M11.7 loader ran in parallel and had some intermittent errors. Both eventually completed.
- **Level 0 vs Level 1 ambiguity**: For some cities (e.g. "Delhi"), only Level 0 (UA total) exists in the PCA-UA file. We prefer Level 1 (city proper) when both exist, fall back to Level 0 (metro total) otherwise. The `level` field in the response tells clients which.
- **"Bruhat Bangalore" prefix**: For Karnataka, the UA is "Bruhat Bangalore UA" (Level 0). We strip the "Bruhat" prefix to match "Bangalore" in our DB.
- **"Greater Mumbai" prefix**: Similar, "Greater Mumbai" → "Mumbai".
- **Naming aliases**: Census of India uses "DMC (U)" for Delhi Municipal Corporation, "NDMC" for New Delhi Municipal Council. We don't match these to "Delhi" / "New Delhi" — that's a future improvement.

## Patterns established (reusable for M11.8+)

- Per-source attribute table pattern: (city_id, ...) + per-source data, release_id
- `cities.in_census_code` column for cross-source joins (FIPS, gisco_id pattern)
- Multi-level matching: prefer Level 1 (city) > Level 0 (metro) > Level 2 (sub-town)
- Alias normalization: strip "Greater", "Bruhat" prefixes; strip "UA" suffix
- `administrative_regions` table for states (not `states`)
- `as string | null` casts for nullable string columns
- Derived metrics: null-safe division with explicit `> 0` check to avoid NaN
- 2-pass matching: build by_key dict, then resolve to our cities by (state, normalized_name)
