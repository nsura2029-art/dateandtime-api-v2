## What we have in the data

### M11.5 (US Census Bureau)

Two distinct data files combined into one per-city table:

1. **2024_Gaz_place_national.txt** (Gazetteer) — released 2024-08-30
   - 32,334 place records (all US places: incorporated + CDPs)
   - Provides: FIPS codes, LSAD, land/water area, internal point lat/lon
   - Source: https://www2.census.gov/geo/docs/maps-data/data/gazetteer/2024_Gazetteer/2024_Gaz_place_national.zip

2. **sub-est2025.csv** (Population Estimates Program) — released 2026-05-14
   - 81,354 rows, 19,483 incorporated places
   - Annual population 2020-2025 (POPESTIMATE2020..POPESTIMATE2025)
   - Source: https://www2.census.gov/programs-surveys/popest/datasets/2020-2025/cities/totals/sub-est2025.csv

## What we get (data layer)

### New table: `us_census_attributes` (migration 147)

```sql
CREATE TABLE us_census_attributes (
  city_id              INTEGER PRIMARY KEY,
  fips_state           TEXT NOT NULL,
  fips_place           TEXT NOT NULL,
  fips_geoid           TEXT NOT NULL,
  lsad_code            INTEGER,        -- 25=city, 43=town, 47=village, 57=CDP, 62=borough
  legal_class          TEXT,           -- "city", "town", "village", "CDP", "borough"
  funcstat             TEXT,           -- 'A' (active) or 'S' (statistical)
  land_area_sqmi       REAL,
  water_area_sqmi      REAL,
  internal_lat         REAL,
  internal_lon         REAL,
  pop_2020             INTEGER,
  pop_2021             INTEGER,
  pop_2022             INTEGER,
  pop_2023             INTEGER,
  pop_2024             INTEGER,
  pop_2025             INTEGER,
  estimates_base_2020  INTEGER,
  release_id           TEXT NOT NULL,
  gaz_release_id       TEXT,
  fetched_at           INTEGER NOT NULL
);
```

10,102 cities loaded. The PRIMARY KEY (city_id) means O(1) join from cities.

## Scenarios we will keep learning from

### Scenario 1: Match rate (85%)

We matched 14,465/17,055 US cities (85%). The 2,590 unmatched are:
- Cities in dr5hn but not in Census 2024 (e.g. very small towns that lost incorporation)
- Cities with different name formats (e.g. dr5hn "NYC" vs Census "New York city")
- Sub-towns (New England) that Census tracks as MCDs (SUMLEV=061), not places

**What we could do**:
- **Fuzzy match** with rapidfuzz (next iteration)
- **Include MCD records** (21K more) — currently we filter SUMLEV=162 only
- **Backfill via alternate names** — dr5hn alt_names vs Census alt names

### Scenario 2: dr5hn population vs Census population

dr5hn's curated population may be older or different from Census. For NYC:
- dr5hn: 8,258,035
- Census 2025: 8,584,629
- Δ: 4% (Census is fresher)

For most cities, the values are within 1-2% (Census reconciles annually). For some small towns, the difference can be larger (e.g. prison towns, military bases).

**Strategy**: We don't overwrite cities.population. The Census data lives in `us_census_attributes.pop_2025` and the API exposes both — clients can choose. Future M11.x can do an intelligent merge (Census for US, dr5hn elsewhere).

### Scenario 3: Vintage tracking

Census vintages are released annually (this is the 2025 vintage, released 2026-05-14). The `release_id` field tracks which vintage a row came from. When the 2026 vintage comes out, we can:
- Load it with a new release_id
- Compare values (year-over-year growth)
- The `populationLatest` will be from the freshest vintage

### Scenario 4: Schema generality for non-US

The us_census_attributes table is US-specific. But the **pattern** generalizes:
- `eu_census_attributes` for M11.6 (Eurostat, schema similar)
- `in_census_attributes` for M11.7 (Census of India)
- `ca_census_attributes` for M11.8 (StatCan)

Each has its own source, vintage tracking, and per-country quirks. The common pattern: (city_id, year) × (population, area, source, release_id).

## Gotchas hit

- **Encoding**: SUB-EST2025 CSV uses Latin-1 (Spanish place names with ñ, á). Used `encoding="latin-1", errors="replace"`.
- **LSAD parsing**: Gazetteer has some non-numeric LSAD values (e.g. "UG" for territories). Used try/except with default 0.
- **Trailing whitespace**: Gazetteer file has wide fields with trailing spaces for visual alignment. Strip all keys/values.
- **Match algorithm**: Initial O(N*M) was too slow (estimated 12+ hours). Switched to O(N+M) via dict-by-state-of-normalized-name.
- **CSV reading**: Used `csv.DictReader` instead of manual splitting to handle quotes properly.
- **FIPS place 5-digit**: Some places have leading zeros (e.g. "00124"). Used `.zfill(5)` everywhere.
- **R2 upload via Python**: boto3 client with Cloudflare R2 endpoint; uses `CF_ACCOUNT_ID.r2.cloudflarestorage.com`.
