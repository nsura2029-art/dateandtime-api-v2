### 2. Source registry API (3 endpoints)

- `GET /api/v1/sources` — list all 10, optional `?active=true`
- `GET /api/v1/sources/:key` — single source + recent releases
- `GET /api/v1/sources/:key/releases` — release history with `?status=` and `?limit=`

### 3. GeoNames ingestion script (4-step pipeline)

`scripts/seed/geonames_cities5000.py` with explicit steps:
- `download` — fetch cities5000.zip (5.6MB)
- `verify` — SHA-256 + row count
- `upload` — R2 raw + manifest (requires CF R2 credentials)
- `register` — write source_releases row

`scripts/seed/geonames_to_staging.py` — parse + stage to local SQLite (proves the pipeline before touching D1).

### 4. Tests (13/13 pass)

`tests/sources.test.ts` covers registry + single source + releases + 404.

## Why GeoNames first (validated)

Even just the staging step proved the value:
- 0 NULL timezones (vs dr5hn 22 unresolved cities)
- 0 NULL population (vs dr5hn 35,546 NULL)
- 245 countries covered (vs dr5hn 223)

GeoNames is the more complete source. dr5hn and GeoNames will be **layered**, not replaced. dr5hn keeps alt_names + translations, GeoNames fills the TZ + population gaps.
