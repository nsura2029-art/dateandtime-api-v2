# M11.3: Unicode CLDR Localized Country Names — Result Report

**Date:** 2026-08-02
**Status:** ✅ APPLIED to D1 + LIVE in API — 5,000 rows, 20 languages, 2 new endpoints
**Branch:** `feature/m11.3-cldr` (ready to merge to develop)

## What we had

| Source | Coverage |
|---|---|
| `countries.name` (dr5hn) | English name for all 250 countries |
| `countries.official_name` (dr5hn) | Local official name in native script (e.g. "Brasil" for Brazil) |
| `country_names` table | **did not exist** — no localized names per language |
| `/api/v1/countries` endpoint | **did not exist** — countries were only nested inside city detail |

The gap: 19 languages × 250 countries = 4,750 translations of country names, not available in any API. The dr5hn `translations` table covers city names but not country names.

## What we did

### 1. Data layer (Migration 145)

- New table `country_names (country_id, language, name, short_name, source, release_id)`
- 3 indexes for fast lookup by (language), (country_id), and (language, name)
- Primary key: `(country_id, language, source)` — multiple sources can contribute to same country

### 2. Loader (scripts/seed/cldr_to_d1.py)

- Downloads Unicode CLDR 48.2 (35MB zip) from cldr.unicode.org
- Extracts 20 target language XML files (en, es, fr, de, zh, ja, ko, ru, ar, hi, pt, it, tr, nl, pl, sv, uk, he, fa, th)
- Parses `<territory type="XX">` elements from each
- Filters: only alpha-2 codes (skips UN M.49 numeric), skips `alt="variant"` (e.g. "Hong Kong SAR China"), keeps `alt="short"` (e.g. "UK")
- Maps each `cca2` to `countries.id`, INSERTs into `country_names` via D1 HTTP API
- 5,000 rows in 3.2 min (26 rows/s, 1 INSERT/call, 16 workers)

### 3. R2 archive (scripts/seed/cldr_publish.sh)

- Bundles 20 XML files into a tarball
- Computes SHA-256 for tarball + each XML
- Generates manifest.json with per-language sizes and hashes
- Uploads to R2 at `r2://dt-data-raw/raw/cldr/territories-48.2/2026-08-02/`
- Registers `cldr-territories-2026-08-02` in `source_releases` with status=`raw-stored`, row_count=5000

### 4. API endpoints (src/routes/countries.ts)

- `GET /api/v1/countries?lang=xx&region=yy&limit=N` — list countries
- `GET /api/v1/countries/{cca2}?lang=xx` — single country
- When `?lang=xx` is given, each country includes a `localized: { name, shortName, languageFallback }` block
- When the requested language has no entry (e.g. Swahili), the English name is returned with `languageFallback: true`
- Full OpenAPI schemas registered, visible in `/openapi.json` and `/docs`

## Gotchas hit (cross-project applicable)

1. **D1 SQL bind limit (~100 vars)**: `cca2 IN (?, ?, ..., ?)` with 100+ values + 1 for `lang` parameter exceeded the limit. Fix: chunk the lookup into batches of 95.
2. **CLDR numeric territory codes (UN M.49)** like `142=Asia` are mixed with alpha-2 codes like `AD=Andorra`. Filter `len(type)==2 and type.isalpha()` to skip the numeric ones.
3. **CLDR has 3 variants**: main entry, `alt="short"` (e.g. "UK"), and `alt="variant"` (e.g. "Hong Kong SAR China"). Skip variant; keep short as a separate column.
4. **D1 source_releases release_id naming**: keep the same `release_id` across loader + R2 publisher — having them diverge causes the R2 archive to point to a release that has 0 rows in the database.
5. **CLDR release choice**: CLDR 48.2 (March 2026) is the latest stable. CLDR 49 is in development.
