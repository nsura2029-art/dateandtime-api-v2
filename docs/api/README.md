## M14 Holidays — Full spec

### 1. `GET /api/v1/filters`
Global catalog of 36 filter codes. Not country-specific.

**Response**:
```json
{
  "success": true,
  "data": {
    "total": 36,
    "filters": [
      {"code": "PUBLIC_NATIONAL", "label": "Federal/National Holidays", "tier": "A1"},
      {"code": "PUBLIC_LOCAL", "label": "Local/State Holidays", "tier": "A2"},
      ...
    ]
  }
}
```

### 2. `GET /api/v1/countries/{cca2}/filters`
Per-country filter list with live counts.

**Query params**:
- `mode` — `country` (default) | `international` | `combined`
- `year` — int, default current
- `from`, `to` — ISO date, default full year

**Response**:
```json
{
  "success": true,
  "data": {
    "countryCode": "US",
    "year": 2026,
    "total": 22,
    "filters": [
      {"code": "PUBLIC_NATIONAL", "rangeCount": 12, "annualCount": 12, "defaultSelected": true},
      ...
    ]
  }
}
```

**Variance**: US=22, NL=4, IN=8, GB=7, NZ=6, DE=10, FR=8, CA=23, AU=11.

### 3. `GET /api/v1/holidays`
Main list. Up to 500 per request.

**Query params**:
- `year` — int (default current)
- `from`, `to` — ISO date (overrides year)
- `country` — ISO 3166-1 alpha-2
- `subdivision` — ISO 3166-2 (e.g. `US-CA`)
- `mode` — country (default) | international | combined
- `filters` — comma-separated filter codes
- `tradition` — religion/tradition filter (e.g. `christian`, `hindu`)
- `source` — data source code (e.g. `calendarific_api`)
- `limit` — 1-500 (default 100)
- `offset` — pagination offset

**Response**:
```json
{
  "success": true,
  "data": {
    "total": 1116,
    "count": 100,
    "holidays": [
      {
        "id": 8523,
        "conceptId": 12,
        "conceptName": "New Year's Day",
        "countryCode": "US",
        "subdivisionCode": "US",
        "startDate": "2026-01-01",
        "endDate": "2026-01-01",
        "observedDate": "2026-01-01",
        "filters": ["PUBLIC_LOCAL"],
        "tradition": "CIVIL",
        "sources": ["calendarific_api"]
      },
      ...
    ]
  }
}
```

### 4. `GET /api/v1/holidays/today`
**Query**: `country`, `days` (0-7, default 0), `limit` (≤500)
**Returns**: Holidays happening today (or within next N days).

### 5. `GET /api/v1/holidays/upcoming`
**Query**: `country`, `days` (1-365, default 30), `limit` (≤500)
**Returns**: Upcoming holidays, sorted by start date.

### 6. `GET /api/v1/holidays/{id}`
**Returns**: Full occurrence detail with sources and provenance.

### 7. `GET /api/v1/long-weekends` (SEO/legacy)
**Query**: `country` (required), `year`, `minDays` (default 3)
**Returns**: 3+ day off-blocks. Simpler algo — no multi-day, no PTO.

### 8. `GET /api/v1/countries/{cca2}/long-weekends/{year}` (Enhanced)
**Path params**: `cca2`, `year`
**Query params**:
- `work_days` — `mon-fri` (default) | `sun-thu` | `fri-sat` | `sat-wed`
- `min_days` — 2-14 (default 3)
- `include_optional` — bool (default true)
- `subdivisions` — comma-separated ISO 3166-2 codes
- `pto` — 0-5 (default 0; >0 includes PTO strategies per LW)

**Response**:
```json
{
  "success": true,
  "data": {
    "countryCode": "US",
    "year": 2026,
    "workDays": "mon-fri",
    "minDays": 3,
    "includeOptional": true,
    "totalLongWeekends": 26,
    "totalDaysOff": 89,
    "summary": {"3-day": 17, "4-day": 7, "5-day": 2},
    "longWeekends": [
      {
        "start": "2026-01-01",
        "end": "2026-01-04",
        "days": 4,
        "type": "4-day",
        "trigger": "New Year's Day",
        "holidays": ["New Year's Day (2026-01-01)", "New Year Holiday (2026-01-02)"],
        "ptoStrategies": [
          {"direction": "before", "ptoDays": ["2025-12-31"], "totalOff": 5, "efficiency": 5.0}
        ]
      }
    ]
  }
}
```

### 10. `GET /api/v1/calendars/holidays.ics`
RFC 5545 ICS file. Multi-day events use exclusive DTEND.
**Query**: `country`, `year`, `subdivision`, `filters`

### 11. `POST /api/v1/feedback`
Submit a holiday correction.
**Body**:
```json
{
  "occurrenceId": 123,
  "type": "wrong_date",
  "comment": "Diwali 2026 is Nov 8 not Nov 7"
}
```
**Returns**: feedback id + vote token.

### 12. `POST /api/v1/feedback/{id}/vote`
**Body**: `{ "token": "abc123", "vote": 1 | -1 }`

## Conventions

- **All dates** are ISO 8601 (`YYYY-MM-DD`).
- **All responses** use `{success: true, data: ...}` wrapper. Errors use `{success: false, error: {code, message}}`.
- **Country codes** are ISO 3166-1 alpha-2.
- **Subdivision codes** are ISO 3166-2 (e.g. `US-CA`, `GB-ENG`).
- **Pagination** uses `limit` + `offset` (not cursor).
- **Rate limits**: 60 req/min per IP (Cloudflare default).

## CORS

All endpoints respond with:
- `Access-Control-Allow-Origin: <requesting origin>` (echoed)
- `Access-Control-Allow-Methods: GET, POST, OPTIONS`
- `Access-Control-Allow-Headers: Content-Type, Authorization`
- `Access-Control-Allow-Credentials: true`

## Caching

- `Cache-Control: public, max-age=300` on most read endpoints
- `Vary: Origin` so per-origin CORS doesn't pollute the cache
- `Cache-Control: no-store` on feedback (writes)

## Versioning

API base `/api/v1/`. Breaking changes get `/api/v2/`. Non-breaking additions go to `/api/v1/`.
