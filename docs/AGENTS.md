# docs/ — project documentation

## Purpose

Markdown documentation that's not auto-generated. Lives alongside `README.md` (the front-page) and `AGENTS.md` (the agent rules).

## Ownership

| File | Owns |
|---|---|
| `setup.md` | Complete local + Docker + Cloudflare setup walkthrough (Windows/macOS/Linux) |
| `troubleshooting.md` | Common issues + fixes (referenced from setup.md) |
| `architecture.md` | (TODO) System design, data flow, deployment topology |
| `adding-endpoints.md` | (TODO) Step-by-step guide for adding new routes |

## Local Contracts

### What goes here

- **Setup guides** — how to get from zero to a running dev env
- **Troubleshooting** — common errors with concrete fixes
- **Architecture** — high-level diagrams and data flow
- **How-tos** — task-oriented guides (e.g. "add an endpoint", "deploy")

### What does NOT go here

- **API reference** — that's at `/docs` (Swagger UI) and `/openapi.json`
- **Endpoint list** — that's in `README.md` (auto-generated by `npm run sync:readme`)
- **Code conventions** — those go in `AGENTS.md` files
- **Auto-generated content** — these docs are hand-written

### Style

- Use clear section headers (`##`, `###`)
- Use tables for command/error references (easier to scan)
- Code blocks with language tags (`bash`, `powershell`, `typescript`)
- Link to other docs and files with relative paths
- Update parent AGENTS.md (root) when adding new top-level doc files

## Work Guidance

### Adding a new doc file

1. Create the file with kebab-case name (e.g. `migration-runbook.md`)
2. Add a row to the table in this file
3. Add a row to the Child DOX Index in root `AGENTS.md`
4. Reference it from setup.md or README.md if it's a top-level need-to-know
